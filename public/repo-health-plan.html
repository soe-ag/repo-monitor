Plan: Repo Health Monitor V1

Build a GitHub repo health dashboard with Next.js + Convex to scan private/public repos, flag outdated packages, and show checklist health at a glance.

Auth: PAT first Scope: Private + Public repos Scan: Weekly + Manual Policy: Configurable updates

Why This Approach

Personal Access Token (PAT) is the easiest implementation path for V1. The GitHub integration will be abstracted so OAuth can be added later without rewriting scan logic.

V1 Scope

Dashboard

  • List all accessible repos (private + public)
  • Display repo cards with package and checklist status
  • Show last scan time and health summary

Checklist Items

  • Tests configured
  • CI/CD workflow exists in .github/workflows
  • README.md exists
  • README updated within 180 days
  • Dependabot config exists

Phased Implementation

Phase 0: Contracts

  1. Define status taxonomy: ok, warning, missing, stale, error, unknown
  2. Set README stale threshold to 180 days
  3. Define package policy enum and default behavior

Phase 1: GitHub Connection

  1. Implement PAT connection + validation
  2. Store connection state and expose UI feedback
  3. Create token-source abstraction for future OAuth

Phase 2: Convex Backend

  1. Add schema tables: connections, repos, package findings, checklist findings, scan runs
  2. Build scan actions for repos, package.json parsing, version checks, checklist checks
  3. Implement weekly scheduled scan + manual scan endpoints
  4. Support partial failures per repo

Phase 3: Frontend Dashboard

  1. Replace starter page with responsive repo-card grid
  2. Show outdated package counts + per-package details
  3. Render checklist indicators and warnings
  4. Add filters (all / needs attention / healthy)
  5. Add scan controls (scan all / per repo)

Phase 4: Verification

  1. Unit tests for semver and checklist evaluators
  2. Integration tests for GitHub ingestion edge cases
  3. UI tests for card/status rendering
  4. CI gate: lint, typecheck, test, build
